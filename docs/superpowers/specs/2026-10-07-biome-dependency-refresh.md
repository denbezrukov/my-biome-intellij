# Refresh Biome after a successful dependency upgrade

A real pnpm 10.5.2 upgrade from Biome 2.2.3 to 2.5.15 leaves WebStorm 2025.3's original 2.2.3 server running. The existing Restart action replaces it correctly. Both facts were measured after successful version-A formatting, with no file reopen after installation.

Automatically use the public project-scoped restart after a dependency replacement is complete enough to execute the selected Biome binaries successfully. WebStorm build 253 exposes only provider-wide project stop/restart; per-server stop/restart belongs to internal implementation APIs. Therefore all Biome servers in the affected IntelliJ project stop, and roots needed by open files restart with their own discovered executable and configuration. Other projects must remain unchanged. Do not add another Restart UI or rely on internal SDK APIs.

The feature applies to Automatic mode. Subscribe to dependency VFS changes only once the project attempts eligible Biome startup. Watch the selected package and its ancestor directories, plus package manifests and standard npm/pnpm/yarn/Bun locks above active roots, including a monorepo lock above the project directory. Handle create, delete, rename, move, content and symlink changes, and debounce bursts for 500 ms. Ordinary source/config edits do not trigger dependency refresh.

Allow a cancellable 30-second retry window when a managed root is initializing or the managed/open-root snapshot changes during verification. Use public server state and 250 ms suspension between checks, with no listener into internal lifecycle APIs.

After a relevant event, resolve the current package for each open root with a running server and probe it through the existing bounded target-aware API outside read actions. Restart only if every active root has a valid selected executable, stable executable identity during verification, and at least one actual executable version differs from the corresponding initialized server version. Missing, malformed or failing replacements preserve the old running servers; later installation events can retry. A relevant event immediately invalidates older pending restart work; debounced collection cancels its remaining verification, with active processes subject to the existing probe cancellation and timeout bounds. Revalidate managed membership, active root selections and the selected Node interpreter before restart. Closed roots, including retained failed instances, do not block healthy open roots. Compare the complete CLI/server semantic version, including prerelease and build metadata. Project disposal cancels pending debounce/probes and prevents restart. Disabled/manual mode does not auto-refresh.

Minimum WebStorm 2025.3 / build 253, compiler JDK 21, existing Kotlin/coroutine and IntelliJ dependencies. No new production dependency, process-kill workaround, executable staging, daemon stop command, Windows/WSL acceptance claim, or shared-global lifecycle state. A valid but same-version reinstall does not force a restart.

Acceptance: real locked 2.2.3 to 2.5.15 install, selected executable provenance, actual new server `serverInfo.version`, and full formatting output from the still-open file. Controls cover event bursts, failed/incomplete install, parent locks, rename/delete/recreate, two roots retaining their own versions/config after the documented project restart, another real project retaining its exact server identity and complete formatting output before/after, and disposal before pending refresh. Additional managed-server controls cover reopening an idle root during a delayed probe, a closed failed root, interpreter changes during verification, superseding install events and complete prerelease version comparisons.
